## Plan: AI Day Phase 1 — Foundation Completion

TL;DR - The repository already has the Vite apps, API health/readiness/public-config endpoints, auth/session foundations, database migrations, and the main provider interfaces. Phase 1 now needs the remaining wiring and a verification pass: real storage signing, a usable AI provider, worker execution, and local migration/dev checks.

**Completed foundations**
* React customer and admin shells.
* Go API health, readiness, public config, structured logging, and graceful shutdown.
* PostgreSQL migrations for the base schema and later payment/asset/job tables.
* Session token hashing, `auth/me`, logout, and auth-mode-gated routes.
* Credit reservation and generation-job transaction primitives.
* Storage and AI provider interfaces, plus Razorpay and comic-pipeline models.

**Remaining work**
1. Keep local secrets out of the repo, confirm `.env` stays ignored, and keep the example env files in sync.
2. Implement a concrete S3/MinIO storage provider and wire it into upload/download intent flows.
3. Implement a mock-first or OpenAI-backed AI provider behind `ai.Provider`.
4. Replace the worker stub in `cmd/worker` with a job loop that claims generation jobs, invokes the AI provider, and stores outputs.
5. Wire provider/config dependencies into `cmd/api/main.go` and `cmd/worker/main.go` so local dev uses the real abstractions.
6. Add a migration runner or Makefile targets that apply and roll back `api/migrations` against local Postgres.
7. Run the local verification pass: `docker compose up -d`, `make api`, `make worker`, `go test ./...`, and the UI/admin dev servers.
8. Add focused integration tests for config validation, upload intents, credit reservation, and generation-job creation.

**Relevant files**
* `api/cmd/api/main.go` - API startup and dependency wiring
* `api/cmd/worker/main.go` - worker entrypoint
* `api/internal/storage/provider.go` - storage provider contract
* `api/internal/ai/provider.go` - AI provider contract
* `api/internal/assets/service.go` - upload intent flow
* `api/migrations/*` - database migrations
* `docker-compose.yml` - postgres, redis, and minio services
* `ui/.env.example`, `admin/.env.example`, `api/.env.example` - local env examples

**Verification**
1. `docker compose up` starts `postgres`, `redis`, and `minio`.
2. `make migrate-up` applies the schema on a fresh local database.
3. `go build ./cmd/api` and `go build ./cmd/worker` succeed.
4. `npm run dev` for `ui` and `admin` starts cleanly and can call `GET /api/v1/config/public`.
5. A mock-provider generation flow can complete end to end: upload intent, upload, create generation, worker processing, and stored output.

**Decisions & assumptions**
* Use MinIO for local object storage.
* Keep payments mocked until the generation pipeline is green.
* Keep the backend rooted in `api/` rather than introducing a separate service tree.

**Open questions**
1. Should the worker run as a separate dev service from day one? Recommendation: yes.
2. Should the first AI backend be mock-only or OpenAI-backed from the start? Recommendation: mock first, then swap in OpenAI once the pipeline is stable.
